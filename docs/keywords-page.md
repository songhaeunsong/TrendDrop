# /keywords 페이지 — 텍스트 기반 트렌드 키워드 추출

작성일: 2026-07-15

## 목적

영상 단위가 아니라 **텍스트 단위**로 "요즘 유행하는 것"을 키워드로 뽑아 보여주는 페이지다.

`/analysis`가 "어떤 영상이 뜨는가"를 보여준다면, `/keywords`는 그 영상들과 검색 데이터에서 **무슨 단어가 반복적으로 등장하는가**를 보여준다.

## 사용한 데이터 소스 3가지

### 1. YouTube 인기 영상의 제목 + 태그

- 엔드포인트: `videos.list?chart=mostPopular&regionCode=KR` (+ 카테고리 5종)
- 비용: 호출당 1 unit, `/analysis`와 같은 30분 캐시를 공유하므로 **추가 비용 0**
- `snippet.tags`에는 업로더가 직접 단 태그가 들어 있어 노이즈가 가장 적은 키워드원이다

### 2. 급상승 영상의 상위 댓글

- 엔드포인트: `commentThreads.list?order=relevance&maxResults=50`
- 비용: 영상당 1 unit
- 대상: 전체 수집 영상 중 **확산 속도(시간당 조회수) 상위 10개** 영상
- `order=relevance`는 좋아요를 많이 받은 댓글 위주로 반환하므로 "많이 공감받은 반응"이 모인다
- 댓글이 비활성화된 영상은 403이 반환되며, 이 경우 빈 배열로 조용히 스킵한다

### 3. Google Trends "Trending Now" RSS

- 주소: `https://trends.google.com/trending/rss?geo=KR`
- 비용: 무료, API 키 불필요
- 한국에서 지금 급등 중인 검색어를 대략적 검색량(`ht:approx_traffic`), 관련 뉴스 제목/링크(`ht:news_item`)와 함께 제공한다
- 정식 개발자 API는 아니므로 포맷 변경 가능성이 있다 — 파싱 실패 시 빈 배열로 처리해 페이지는 계속 뜨게 했다

## 추출 파이프라인

```
영상 제목·태그 ──┐
상위 댓글 500개  ├→ 토큰화 → 불용어 제거 → 조사 제거 → 가중치 합산 → 랭킹
급등 검색어      ┘
```

구현 위치: `lib/keyword-extract.ts`

### 토큰화 (tokenize)

1. URL, 이모지, `ㅋㅋ`/`ㅠㅠ` 류 반복 자모 제거
2. 문자·숫자 외 특수문자 제거 후 공백 분리
3. 토큰 끝의 조사 제거 (`여행을` → `여행`) — 남는 길이가 2자 이상일 때만 적용해 `종이` 같은 단어가 `종`으로 망가지지 않게 함
4. 2자 미만, 숫자만, 자모만("ㅋㅋ"), 불용어 목록에 있는 토큰 제외

불용어는 댓글에서 흔하지만 트렌드 정보가 없는 단어들("진짜", "너무", "좋아요", "구독" 등) 약 100개를 하드코딩했다. 형태소 분석기 없이 규칙 기반으로 시작한 것이라 완벽하지 않다.

### 가중치 설계

| 소스 | 점수 | 이유 |
|---|---|---|
| 급등 검색어 (RSS) | 40 × 검색량 가중치 | Google이 이미 "급등"으로 검증한 키워드 |
| 영상 태그 | 6 × 영상 반응 가중치 | 업로더가 단 정제된 키워드 |
| 영상 제목 | 3 × 영상 반응 가중치 | 정제되어 있지만 어그로성 표현 포함 |
| 댓글 | (1 + min(댓글 좋아요/50, 4)) × 영상 반응 가중치 | 노이즈가 많아 기본 점수는 낮게, 공감(좋아요)에 가중 |

**영상 반응 가중치** — 반응이 큰 영상에서 나온 키워드일수록 높게 친다:

```
가중치 = 1 + log10(시간당 조회수)/2 + min(영상 좋아요/100,000, 0.5)
```

- 로그 스케일이라 대략 1~3.5배 범위에 머문다. 조회수가 10배 커져도 가중치는 0.5만 늘어서, 메가 히트 영상 하나가 랭킹 전체를 삼키지 않게 했다
- 급등 검색어도 같은 원리로 대략적 검색량(`200+`, `2000+`)에 로그 가중치를 적용한다

- 같은 댓글 안에서 반복된 단어는 1회만 계산한다 (도배 방지)
- 최종 랭킹은 **2회 이상 언급되었거나 급등 검색어인 키워드**만 남긴다 (1회짜리 우연 제거)
- 여러 소스에 동시에 등장하면 점수가 자연스럽게 합산되어 교차 검증 효과가 난다

## 쿼터 계산

30분 캐시 기준 최악의 경우:

- mostPopular 6회 × 48회/일 = 288 units (analysis 페이지와 공유)
- commentThreads 10회 × 48회/일 = 480 units
- RSS = 0

합계 약 770 units/일로 무료 쿼터(10,000)의 8% 수준이다.

## 페이지 구성

- **통합 키워드 랭킹**: 세 소스 합산 점수 순 상위 30개. 키워드별로 출처 배지(급등 검색어/영상 태그/영상 제목/댓글), 언급 횟수, 발견된 맥락 예시를 표시
- **급등 검색어 섹션**: RSS 원본 데이터를 뉴스 링크와 함께 그대로 노출 — "뉴스 맥락 연결"(MVP P2-9) 기능의 프로토타입

## 현재 한계와 다음 단계

1. **형태소 분석 부재** — 규칙 기반 조사 제거라 복합어/활용형 처리가 불완전하다. 품질을 올리려면 한국어 형태소 분석기 도입 또는 LLM(Claude API) 기반 추출로 업그레이드
2. **"왜 뜨는지" 요약 없음** — 지금은 키워드와 출처만 보여준다. 댓글 뭉치를 LLM에 넘겨 한 줄 요약을 생성하면 MVP P1-2(트렌드 상세)로 이어진다
3. **스냅샷 미저장** — 매 갱신마다 계산만 하고 버린다. Neon DB에 랭킹을 저장하면 "어제 대비 순위 변동" 같은 시계열 기능이 가능해진다
